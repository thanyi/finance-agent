# 东方财富账户只读连接验证

验证日期：2026-10-15（Asia/Shanghai）。

## 结论

已在本机 Parallels 的 Windows 11 ARM 中连接正在运行、已登录的东方财富终端 12.1.1，并通过客户端正常的数据导出功能读取资金和 3 条持仓。

本节记录封装前的单次可行性验证；后续刷新、认证及重启的结果见文末「Skill 封装及扩展验证」。交易执行能力不在本次验证范围内。

## 实测接入路径

1. Mac 通过 `prlctl` 识别运行中的 Windows 虚拟机。
2. `prlctl exec <虚拟机> --current-user ...` 可以在已登录的 Windows 桌面会话中运行诊断。默认执行位于系统会话，不能直接用于访问登录桌面的界面。
3. 通过 Win32 窗口枚举识别东方财富证券交易窗口；不能仅依赖进程的 `MainWindowHandle`，它可能指向行情主窗口。
4. 当前交易面板为自绘控件。UI Automation 在本次探测中只暴露 `CElementFrameWnd_DC`、`ContainerWnd_DC` 等容器，没有暴露持仓单元格和对应的数据读取模式。
5. 持仓表右键菜单提供「数据导出」，可打开 XLSX 导出向导。
6. 导出向导的文件名输入框和步骤按钮可以通过 Win32 控件句柄操作。验证时设置文件名后回读核对，再推进导出步骤。
7. Mac 从 Parallels 共享目录读取客户端生成的 XLSX，并解析为本地 JSON。

打开自绘表格的导出菜单仍使用了经截图检查的坐标，因此目前是混合方式的验证原型。后续实现需要针对窗口位置、尺寸、缩放、当前页面和弹窗做校验，并在无法确定界面状态时停止。

长探测脚本在本次通过命令行传递时出现超时，改用共享目录中的临时脚本后可执行。实现时应使用脚本文件传递，不能把本次现象推广为某个已确认的命令长度上限。

## 下一阶段实施范围

建议先实现可重复运行的只读采集器：动态定位交易窗口、检查当前页面、刷新持仓、导出到唯一文件名、核对生成时间和文件完整性、解析并显示资金与持仓。成功、失败、过期和空持仓应有明确且独立的状态；失败时保留上次快照并标记过期，不把旧快照当作本次成功结果。

只读版本验收应覆盖正常刷新、客户端重启、登录失效、虚拟机暂停恢复、未知弹窗，以及窗口尺寸或缩放变化。完成后再确定交易方式及后续执行范围。
