# Windows 本机认证、重启与资金核对

以下操作改变客户端会话或面板，仅在当前任务已要求时执行，沿用已有授权。

## 退出和恢复

运行 `test --scenario logout`，保存退出截图；确认认证要求后实际尝试一次采集，检查其报告 `auth_required`。未知确认框需检查，不把退出请求已发送当作已退出。

若出现 `EMCustomTipDlg`，只有截图明确显示「您确定要退出交易系统吗？」与「是，退出／否，最小化」时，才能用 `test --scenario logout --reviewed-screenshot <该测试目录>/screen.png` 继续。该操作校验当前对话框身份和尺寸，不能用来确认其他提示。此客户端退出后可能直接关闭交易面板而不显示登录框，因此结合明确的退出记录识别认证要求；仅折叠界面仍报告交易面板不可用。模态框禁用交易窗口时，普通采集和填单均停止。

主动退出验证认证缺失路径。自然会话超时另用故障注入测试，不能混称为已等待服务端超时。

用户人工重登后，重新 `doctor --open-trade`、核对账户并按需校准，再运行 `test --scenario resume`。将新快照关联前面的退出记录后才可判完整恢复通过；未重登时保持待人工处理。

退出／重启会使原校准失效。恢复时必须用新会话截图重新校准，并显式传入从截图核对的同一脱敏账户标识。脚本将恢复结果与 `recovery.json` 中的先前测试关联，不接受没有先前事件的恢复通过结论。

## 重启

运行 `test --scenario restart`。正常关闭已识别主窗口，确认进程退出后从已发现路径启动；不强制结束进程。若只缩入托盘或出现确认框，报告 `restart_pending` 并检查界面。新进程存在不等于恢复成功，仍需核对账户并采集。

经典版12.1.1可能在退出时出现标题为「提示」的推广弹窗。先运行 `doctor` 留存新截图，只有截图明确显示推广内容和底部「继续退出」时，才执行 `test --scenario restart --reviewed-screenshot <该诊断目录>/screen.png`。脚本核对弹窗进程、身份、尺寸、DPI、版本与点击归属，点击底部继续退出；不能用该入口接受其他提示。启动画面尚在加载或交易面板缺失时，先重新诊断，不立即断言需要认证。

## 资金口径

`reconcile` 对当前快照做持仓市值和资金核对。`test --scenario funds` 展示资金面板并保存截图；检查后再次执行将面板还原，核对截图后再采集。

普通人民币现金账户需取得资金余额、冻结分项、对应未结委托和资产口径。可用、可取、余额不可互换；资金余额是否包含冻结资金要按客户端定义确认。

仅在同一快照且资金余额已含冻结资金的明确口径下，核对：总资产＝资金余额＋证券市值＋明确列示的其他资产－负债，并单独核对委托冻结金额。未显示的其他资产、负债不能自行置零。字段缺失时保持 `partial`，列出缺失和差额。

`reconcile --funds-evidence <JSON>` 要求 `source_file` 指向相对于证据JSON的本地运行产物，并核对 `source_sha256`；还要求关联当前快照哈希、人民币币种和明确口径。源文件真实存在不代表数字已核实，必须逐项检查证据后才能声明口径已确认。不得用猜测数值构造通过。正常界面、导出和查询仍无法取得的字段属于能力限制。

Windows原生版恢复数据位于 `%LOCALAPPDATA%\FinanceAgent\eastmoney-windows`。在本机重新诊断和校准；不要复制Mac版运行目录。远程连接中断或锁屏时先恢复可操作的Windows桌面，再重新识别窗口。
