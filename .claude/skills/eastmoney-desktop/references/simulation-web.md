# 东方财富官方模拟盘

用于用户明确要求在东方财富模拟账户中测试提交、买卖或撤单的任务。桌面证券账户仍维持不提交委托的边界。

## 入口与账户

2026-10-16检查的官方入口：

- [创建模拟组合](https://group.eastmoney.com/createcom.html)：页面将组合定义为模拟资金账户，并列出对外隐藏选项。
- [模拟交易室](https://group.eastmoney.com/room/index.html)：提供买入、卖出、挂单、持仓、当日委托、当日成交和资金流水。

网站账户和Windows证券交易客户端的认证相互独立。人工在网页中完成登录，不读取密码、短信或其他应用中的认证信息。用户已有多个组合时明确选择目标。使用已有组合做用户要求的测试时记录初始状态；若需新建测试组合，使用清楚的测试名称并设为仅自己可见。不擅自更改现有组合名称、公开状态或删除组合。

## 执行及证据

先核对当前页面的主机严格为 `group.eastmoney.com`、路径为已检查的模拟交易页面，再核对模拟组合标识、名称、虚拟资金、已有持仓和未结委托。网站导航含实盘证券交易链接，不进入这些链接。重定向、未知弹窗、组合选择不明确时停止。

先记录余额、持仓及委托；选择模拟盘支持的标的及明确参考价，使用最小测试数量。提交前回读方向、代码、价格、数量及目标组合。一次提交后查询委托编号和状态，再查询成交与资金变化；超时和回报未知时先查单，不能盲目重发。

买入、卖出、未成交订单撤单分别记录结果。卖出限已有可卖数量；没有可卖持仓或模拟盘限制当日卖出时，如实记录限制，不伪造持仓和成交。只撤本次创建且编号明确的测试委托；撤单请求成功不等于最终撤成，需查询最终回报。

浏览器截图、订单编号、资金和账户信息仅放在Git忽略的 `data/eastmoney/official-simulation/`。每项区分已提交、已受理、已成交、已撤、拒绝和结果未知。自动化框架或页面可打开不能记为模拟交易通过。

## 已验证的网页操作

本流程以页面元素操作，未新增直接调用后台交易接口的脚本。六个桌面CLI命令也不会提交官方模拟盘订单；`test --scenario simulation` 仍是独立的本地状态机测试。

1. 从「我的组合」核对用户拥有的组合，再进入对应模拟交易室。读取页面 `#hptZjzh` 作为本次目标组合的标识；每次提交前与已核对标识比较，不能只检查页面标题或输入框代码。
2. 下方 `li[data-type="ccxx"]`、`gd`、`drwt`、`drcj` 分别切换持仓、挂单、当日委托及当日成交。持仓行形如 `#ccxx<代码>`，其中 `.kysl` 是可用数量。记录原始持仓、资金和已有订单。
3. `span.tab_buy`、`span.tab_sale` 切换方向；`#futcode` 输入代码后等待建议列表，核对对应行 `data-stockdata` 中的代码、名称和市场，再点击该建议。等待 `[data-bind="f57"]` 与目标代码一致且报价更新，不能在代码标题已变、价格仍旧时填写。输入建议可能异步返回，首次空列表不能立即判不支持。
4. `#price`、`#codenumber` 分别填写价格和数量；`#gt10`、`#gt3` 是页面显示的跌停、涨停限价。本轮为了测试撮合分别使用页面涨停价买入、跌停价卖出，均为100份；撤单测试用页面跌停价买入，先核对其低于当前买价。这些是测试条件，不是投资策略或未来测试的固定价格。
5. 等待 `#btnOrder` 可用，重新回读方向、代码、价格、数量和目标组合；先写本地提交意图，再点击一次。**本轮买卖按钮直接提交，没有二次确认框。** 数值填写后的按钮状态会延迟更新，等待其可用，不能强制启用或重复点击。
6. 切换当日委托后等待新订单行加载，形如 `#drwt<合同编号>`。本版各列为委托时间、状态、代码、名称、方向、委托价、委托数量、成交数量、成交均价、合同编号。只有状态「全部成交」且数量、方向及编号匹配才记为成交；当日成交 `#drcj<编号>` 另核对成交金额和手续费。分页切换后旧行可能短暂保留，不能仅以行存在判新状态。
7. 撤单先查该测试委托确实未成交，再在挂单中定位 `#gd<合同编号>`；同时核对 `data-wth`、`data-code`、数量、价格，再点击该行 `.chedan`。只处理 `#Cxc_Dialog .question` 文案准确为「确认撤单？」的确认框，在核对同一目标后点击 `#btnCxcConfirm`。保持同一浏览器控制会话完成这两步；提示消失时先查单，不把已打开确认框等同已发送撤单。
8. 等待当日委托中对应编号的最终状态「全部撤单」，成交数量为0；核对该挂单消失、冻结为0及可用余额回补。随后清空代码、价格、数量，并确认买卖按钮禁用。撮合竞态导致已成交时如实记录，不再次提交订单来伪造撤单通过。

## 实测结果（2026-10-16，Asia/Shanghai）

本轮使用用户唯一的官方模拟组合及已有可卖持仓，没有新建或更改组合设置：

| 项目 | 结果 |
|---|---|
| 模拟买入159915、100份 | 官方模拟盘实测通过：全部成交，合同及成交记录一致 |
| 模拟卖出159915、100份 | 官方模拟盘实测通过：卖出原有可用份额，全部成交 |
| 限价买入100份后撤单 | 官方模拟盘实测通过：未成交挂单最终全部撤单、成交0份 |
| 资金及数量核对 | 本次模拟资金流水实测通过：买卖成交金额与手续费解释余额变化；撤单冻结全额释放；净持仓数量变化为0 |
| 清理 | 无遗留挂单，填单区清空，提交按钮禁用 |

买入后总持仓增加但可用份额未增加；卖出原有份额后，总持仓恢复原数量，可用份额比测试前减少100，符合本次模拟盘展示的当日买入不可卖行为。不可为了恢复可用数量而补单。账户、资金、合同编号及截图只保留在本地证据中。本轮结果不证明实盘提交能力，也不替代实盘完整资金对账。

证据根目录为 `data/eastmoney/official-simulation/`：

- `test-report.json`：逐项结果、资金检查及原始文件SHA-256；`progress.json` 状态为completed。
- `runs/20261016-104743-4d34d7a64a-initial-state/`：初始账户与持仓。
- `runs/20261016-105259-c606248e9b-official-buy/`：买入意图、订单和成交回报。
- `runs/20261016-105512-91455f5b4f-official-sell/`：卖出意图、订单和成交回报。
- `runs/20261016-105634-9121900185-official-cancel/`：挂单、冻结、确认框、最终撤单状态和解冻证据。
- `final-orders.json`、`final-state.json` 及同名前缀PNG：最终委托、持仓及清空状态。个别早期截图超时，已保留DOM，最终截图已完成检查。
