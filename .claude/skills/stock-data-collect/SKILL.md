# stock-data-collect

输入六位A股代码，例如 `/stock-data-collect 600519`。沪深与北交所按代码路由；北交所不请求 BaoStock 或新浪沪深接口。

## 执行采集

本仓库根目录由 `scripts/collect_finance.py` 与 `CLAUDE.md` 确认。Claude 与 Codex 使用相同脚本；不要依赖调用时的工作目录，也不要将股票代码用作指数代码。

在仓库根目录执行（推荐 Python 3.11+）：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/collect_finance.py stock 600519
```

已存在可用环境时直接运行最后一条，替换代码。默认输出到独立的 `data/stock_<代码>_<时间>/`；可用 `--output` 指定新目录。每次接口调用限时35秒，瞬时网络错误最多重试1次；可用 `--timeout`、`--retries` 调整。不修改全局代理设置，不覆盖既有采集目录。

必须读取输出 `report.json` 的 `datasets`、`metrics`、`limitations`，并打开分析所需的 CSV。逐项核对指标的 `value/status/source/asof`；`status=partial` 是有明确缺失项的部分结果。接口返回原始表、公告索引或某个财务指标，不代表分析所需字段齐全。人工从公告补到的证据在分析中单独注明原文出处，不把脚本报告的 `missing` 改写成接口已采集。

## 数据选择与口径

| 数据 | 主路径 | 降级/核验 |
|---|---|---|
| 合并利润表、资产负债表、现金流量表 | 东方财富 `stock_*_sheet_by_report_em` | 新浪 `stock_financial_report_sina`；冲突回查公告 |
| 资产与负债交叉核验 | 东财/新浪同报告期绝对金额 | 相差超过1%标记冲突，逐期核对年报 |
| 日线与收盘估值 | BaoStock 不复权行情，含 `peTTM/pbMRQ/psTTM` 和同源5年经验分位 | 东财/新浪日线；PE/PB缺失时百度 `stock_zh_valuation_baidu`，PS缺失须标注；无完整同口径历史不输出分位 |
| 财务指标、扣非利润/ROE等原始证据 | `stock_financial_analysis_indicator_em` | 年报原文核验，原字段保存在CSV |
| 分红、股东人数、流通股东、主营构成 | 新浪/东方财富对应单股接口 | 公司定期报告 |
| 近6年公告索引 | 巨潮 `stock_zh_a_disclosure_report_cninfo` | 交易所公告；须打开原文，不把索引当全文 |
| 新闻线索 | `search_news.py`：Tavily（可选密钥）→东方财富单股新闻 | 不代替公告或完整新闻历史 |

原始表保存为 `*_raw.csv`；标准化财报 `profit.csv/balance.csv/cashflow.csv` 金额为人民币元；`*_annual.csv` 单独保存近5个年报期。报告含各年报期列表及连续5年覆盖检查。

- 利润和现金流是年初至报告期累计，半年报不得当全年值；资产负债表为期末值。优先并列最近完整年报与最新已披露中报/季报；现金流和资本支出先做相同期间的同比，再判断全年趋势，不把半年度FCF为负直接当成全年恶化。
- `latest_fcf` = 同一报表、同一报告期 CFO − 购建固定资产、无形资产和其他长期资产支付现金。资本支出缺失不补零，不称为FCFF或FCFE；银行、保险等需专门估值方法。
- 年度净利润/股本不是TTM EPS；总净利润与归母净利润分别保留；不得用ROE倒推PB。
- 扣非加权ROE以披露口径核验，不以扣非净利润除以简单平均净资产冒充披露值。
- 标准化资产负债表保留应收账款、存货、流动资产/负债及主要借款项目；缺失的债务分项不补零，不能直接相加冒充完整有息负债。EV/EBITDA须另核同日市值、所有有息负债与TTM EBITDA，否则标注缺失。
- `last_close` 为截至昨日及之前的收盘价，不是实时价。用户问“现在”或交易日收盘后分析时，再核对可用的当日收盘行情；若仍未取得，只陈述 `asof` 日价格与估值，不称其为今日或实时行情。股票价格不复权，仅供报价与估值核对；跨除权日的收益、52周价格比较须另取并注明一致复权口径。
- `NOTICE_DATE/UPDATE_DATE` 等披露、修订字段在原表中保留。这里取得的是查询时最新修订版本，不能用于声称无前视偏差的历史回测。
- 原始附加表须按真实日期排序：股东人数不能假定 `tail()` 是最新；主营构成先解析报告日期，再分别选择最新年报与最新季报。按产品与按地区不可混加。
- 估值分位以同源、同口径、有效日频样本计算，解释为“样本中不高于当前值的比例”；展示样本范围与数量。分位、历史均值或中位数都不是内在价值，极端盈利年度会扭曲PE均值。

## 补齐自动接口未覆盖的证据

按 M1–M6 所需逐项补齐，不得因脚本结束就进入完整评分：

1. 从年报/季报核对关键报表项目、币种、合并范围、审计状态、扣非ROE、有息负债及资本支出口径，记录公告链接和页码。报告期、公告日、订单统计截止日分别标注。
2. 从公告核对管理层薪酬与持股、客户/供应商集中度、审计意见、增减持/质押/并购等重大事项。公告表只是检索入口；年报中的现任与离任人员口径不能混称。订单中的“其中”是包含关系，订单不是已实现收入或利润。
3. 核实公司业务后选择至少3家可比同行，分别采集同期财报与估值；业务结构差异大时只作参考，不硬算“行业均值”。不能用示例公司的行业、静态PE替代TTM对照。
4. 检查连续5个年报期是否覆盖、最新季度是否已入库、关键列是否为空、跨源冲突是否已解决。金融企业不得套用一般工商企业的负债率阈值。
5. 股东户数变化只说明账户分布，不能据此断定机构卖出或散户接盘；香港中央结算有限公司持股变动也不是北向日净流入。2024-08-19后公开北向买卖额披露调整，近10/20日净流入默认缺失；不使用成交总额、额度余额、旧历史或单日快照推算。

每个采用的数值附来源接口/原文链接、查询时间、数据日期和单位。每个未取得的项目写 `[数据缺失：具体原因]`；数据冲突用 ⚠️ 标注。缺失数据不能支持数值预测或精确评级。

接口覆盖、权限、验收结果与限制见仓库 [docs/data-sources.md](../../../docs/data-sources.md)。采集完成后交给 `analyze-stock`，保留原始数据路径与缺失说明。
