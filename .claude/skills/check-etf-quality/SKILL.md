# check-etf-quality

**这个 skill 只回答一件事：**
> 我决定配置这个指数了，哪个 ETF 更适合作为实现工具？

它聚焦于 ETF 作为"工具"的质量，不重复做指数层面的估值和择时分析。

---

## 使用方式

```
/check-etf-quality [指数名称 或 多个ETF代码]

示例一：给我找追踪创业板的ETF并比较
/check-etf-quality 创业板指（399006）

示例二：指定几个ETF横向比较
/check-etf-quality 159915 vs 159952 vs 159967

示例三：只查一个ETF是否够格
/check-etf-quality 513100（纳指ETF）
```

---

## 何时调用这个 skill？

```
✅ 需要调用的情况：
→ 决定配置某指数，但不知道选哪个 ETF（同指数有多个可选）
→ 持有某 ETF 但规模缩水、溢价异常，想确认是否需要换仓
→ 第一次为某个指数配置，没有现成持仓

⏩ 不需要调用的情况：
→ 已持有该指数的主流大型 ETF（规模>50亿），近期无异常
→ 只是想判断"该指数现在该不该买"（用 choose-index-now）
→ 只是想确认介入时点（用 check-entry-timing）
```

## 执行数据采集

先确认候选ETF代码及共同跟踪基准；输入指数时，从基金公司/交易所核实候选，不根据名称相似就视为同指数。定位含 `scripts/collect_finance.py` 的仓库根目录，对每个候选执行：

```bash
.venv/bin/python scripts/collect_finance.py etf 510300
```

Python环境依赖见仓库 `requirements.txt`。读取输出 `report.json` 和原始CSV：行情用东财→新浪；净值与运作费用用天天基金；基本信息用同花顺→雪球；份额用上交所/深交所；持仓取当年及上一年报表。所有接口都有调用时限，失败保留原因。

- `avg_amount_3m` 按近3个自然月计算日均成交额，单位元；不可把成交量当成交额。
- `close_premium` 仅由同日未复权收盘价和单位净值计算，不是实时IOPV溢价，净值日期不匹配则缺失。
- `reported_aum` 为天天基金档案中带披露日期的净资产规模，不是实时值；管理费/托管费可提取但生效日仍须核验。
- `aum` 仅在交易所份额统计日期与单位净值日期一致时计算；份额规模（份）不是资产规模（元）。深交所接口若无统计日期，不能猜日期相乘。
- 费用、跟踪基准、复制方式须回查最新招募说明书/公告，保留生效日。字段存在不代表已完成核验。
- TE/TD优先取基金定期报告；自行计算须获得分红再投资净值与同币种同口径的基准收益序列。累计净值不是分红再投资净值，ETF成交价也不能替代基金净值。
- 基金净值页的“申购状态”不能当作场内一级市场申赎状态，应查基金公司PCF及公告。
- `status=partial` 时逐项补齐缺失证据；缺少核心规模、费率或基准核验，不得输出完整排名。

详细接口与范围见仓库 [docs/data-sources.md](../../../docs/data-sources.md)。

## 数据采集清单

```
对每个候选 ETF 采集：
[ ] ETF 名称、基金公司、成立日期
[ ] 管理费率 + 托管费率（总费率）
[ ] 当前规模（AUM）及近6个月规模变化趋势
[ ] 追踪指数名称与代码（确认是否相同指数）
[ ] 年化跟踪误差（TE）
[ ] 近1年跟踪偏差（TD）
[ ] 复制方式（完全/抽样/合成）
[ ] 近3个月日均成交额
[ ] 当前溢折价率
[ ] 前10大持仓及合计权重（最新季报）

数据缺失须标注 [数据缺失：原因]，不得跳过。
```

## 核查维度一：这个 ETF 安全吗？

**规模判断**

```
AUM > 50亿  → ✅ 规模充足，仍须单独核查实际成交与价差
AUM 10~50亿 → ✅ 正常运营
AUM 2~10亿  → 🟡 偏小，关注规模变化趋势
AUM < 2亿   → ⚠️ 规模偏小，核对基金合同的终止条款和持续经营情况

⚠️ 清盘条件依基金合同及现行规定核对；不能把统一规模阈值当作自动清盘条件。
规模缩减须区分原因：净值下跌（被动）vs 持续净赎回（主动流出，更需警惕）
```

**费率判断**

```
总费率 = 管理费率 + 托管费率

以各基金最新招募说明书与公告为准，比较同一指数候选产品的实际费率；交易佣金与买卖价差也会影响总成本。
```

```
【安全性小结】
AUM：[X亿]  状态：[✅健康 / 🟡偏小 / ⚠️警戒]
总费率：[X%]  vs 行业均值：[低/持平/偏高]
```

## 核查维度二：这个 ETF 跟得准吗？

**跟踪误差（TE）**——日常波动层面的偏离

下列 TE、规模和成交额分档仅作初筛；须结合 ETF 类型、跟踪基准和当前市场条件核对。

```
年化 TE = StdDev(ETF复权净值日收益率 - 同口径基准指数日收益率) × √252
计算前核对净值/指数的币种、分红处理、交易日和收益口径；样本不足时标注缺失。

< 0.3%    → ⭐⭐⭐⭐⭐ 旗舰水准
0.3~0.8%  → ⭐⭐⭐⭐  良好
0.8~1.5%  → ⭐⭐⭐   可接受
> 1.5%    → ⚠️ 较差，可能存在额外损耗
```

**跟踪偏差（TD）**——长期收益层面的偏离

```
近1年 TD = ETF复权净值收益率 - 同期基准指数收益率
费用可能已反映在净值中；股息、现金拖累、汇率与抽样复制也会影响 TD，不能只凭费率解释。

TD ≈ -费率         → ✅ 正常，如实反映费率损耗
TD 明显优于 -费率   → ✅ 有额外收益（如证券出借、打新收益）
TD 明显差于 -费率   → ⚠️ 存在额外损耗，需查明原因
```

```
【跟踪质量小结】
年化 TE：[X%]  → [⭐⭐⭐⭐⭐ / ⭐⭐⭐⭐ / ⭐⭐⭐ / ⚠️]
近1年 TD：[X%]  vs 费率 -[X%]  → [✅正常 / ✅有超额 / ⚠️有损耗]
复制方式：[完全/抽样/合成]
```

## 核查维度三：这个 ETF 买得进卖得出吗？

```
日均成交额（近3个月）：

> 10亿   → ✅✅ 旗舰级，机构也能大额操作
1~10亿   → ✅  普通投资者无障碍
0.1~1亿  → 🟡  偏低，注意买卖价差
< 0.1亿  → ⚠️  严重不足，慎入

当前溢折价率（注明净值或 IOPV 的时间戳）：
-0.2% ~ +0.2% → ✅ 正常
> +0.5%        → ⚠️ 溢价过高，追高风险
< -0.5%        → 需判断原因（套利机会 or 流动性问题）

QDII ETF 须额外核对海外市场交易时差、汇率及 IOPV 时效；旧 IOPV 算出的溢价不得当作实时套利空间。

申赎状态：
正常开放 → ✅ 套利机制有效，溢折价可自我修复
暂停申购 → ⚠️ 溢价难以消退，谨慎追高
```

```
【流动性小结】
日均成交额：[X亿]  → [✅✅ / ✅ / 🟡 / ⚠️]
溢折价率：[X%]    → [✅正常 / ⚠️偏高 / 需确认]
申赎状态：[正常/暂停申购/暂停赎回]
```

## 横向比较（同指数多 ETF 时）

当同一指数有多个 ETF 可选时，按以下优先级决策：

```
优先级排序逻辑：

第一关（硬性筛选，不达标直接淘汰）：
→ AUM < 2亿 → 优先排查基金合同终止条款及流动性，不能仅凭规模判定清盘
→ 申赎暂停 且 溢价 > 1% → 排除

第二关（主要比较维度）：
→ 总费率：同等条件下，费率低的优先
→ 日均成交额：越大越好（流动性保障）
→ 年化 TE：越小越好（跟踪精准）

第三关（决胜维度，前两关相近时）：
→ TD vs 费率：哪个超额更多（打新/出借收益）
→ 基金公司口碑及运营年限

实用结论：
对于创业板、纳指等主流大型指数，
通常规模最大 + 费率最低 + 成交额最高的那个 ETF
就是最优工具，不需要过度分析。
```
